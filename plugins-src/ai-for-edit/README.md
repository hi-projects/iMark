# AI for Edit

用你自己配置的 AI 服务，整理当前文档的 Markdown 排版，或者在空文档里按一句话生成内容。

插件只负责「把文档发给 AI、把结果放进预览」；**点确认之前不会改文档**。不内置任何
AI 账号，也不经过 iMark 的服务器。

## 配置

在「设置 → 插件 → AI for Edit」里填写：

| 字段 | 说明 |
| --- | --- |
| 服务地址 | 可以配置多个，按列表顺序逐个尝试：前一个连接失败、超时或返回 HTTP 错误时自动换下一个。每个地址要填**完整的接口路径**，例如 `https://api.deepseek.com/chat/completions`（OpenAI 兼容）或 `https://api.anthropic.com/v1/messages`（Anthropic 兼容）；插件不再自动补全 `/v1/...`。 |
| 服务模型 | **每个地址单独一份**，卡片里跟着地址填写。默认地址是 `deepseek-flash`；换其它服务时填该服务支持的模型名，例如 `gpt-4o-mini`、`moonshot-v1-8k`、`qwen2.5:7b`。Azure 的部署名在地址路径里，这一项可以留空。 |
| API 密钥 | **每个地址单独一份**，同样在卡片里填写；换地址时不会串用。密钥加密保存在本机，只会随请求发送到对应的那个服务地址。本机/内网服务（localhost、127.x、192.168.x 等）不需要密钥时可留空；公网地址没填会列在卡片上方的「未完成」提示里。 |
| 请求超时 | **单个地址**的响应超时，默认 60 秒，范围 5–90 秒。慢模型可以调大；超时后会尝试下一个地址。 |
| 把扫描页作为图片发送 | 默认开启。PDF 里没有文字层的页面（扫描件）会渲染成 JPEG，随请求一起发给模型；需要模型支持图像输入。关掉后这些页面会被跳过，只发送有文字层的部分。 |
| 生成提示词 | 用于「生成」的 system 提示词。设置页预填内置默认值，可以整段替换；点标题旁的恢复图标可还原默认值。 |
| 美化提示词 | 用于「美化」的 system 提示词，同样是整段替换。面板里这一轮填写的美化要求仍会追加在提示词之后。 |
| 显示浮动小人 | 在编辑器里显示一个会动的小人，点它打开对话，按住可以拖到任意位置。默认开启。 |
| 小人形象 | 猫咪 🐱 / 企鹅（动画）🐧 / 机器人 🤖 / 幽灵 👻 / 星星 ✨。企鹅是内置的矢量动画形象。 |

默认配置就是 DeepSeek（`deepseek-flash`）。常见服务地址：

- DeepSeek（OpenAI 兼容）：`https://api.deepseek.com/chat/completions`（默认）
- DeepSeek（Anthropic 兼容）：`https://api.deepseek.com/anthropic/v1/messages`
- OpenAI：`https://api.openai.com/v1/chat/completions`
- Moonshot：`https://api.moonshot.cn/v1/chat/completions`
- 智谱：`https://open.bigmodel.cn/api/paas/v4/chat/completions`
- Anthropic：`https://api.anthropic.com/v1/messages`
- Ollama：`http://127.0.0.1:11434/v1/chat/completions`（模型填 `qwen2.5:7b` 之类）
- Azure OpenAI：`https://<资源名>.openai.azure.com/openai/deployments/<部署名>/chat/completions?api-version=2024-06-01`

配置完成后可以点顶部的「测试连接」逐个确认所有地址、密钥与模型是否可用；每个地址
卡片上的「测试连接」只测那一行。失败时插件会按顺序继续尝试，直到某个地址成功；
全部失败才会报错，明细里逐个列出每个地址的原因。

### 提示词

生成与美化各有一条 system 提示词，默认值直接显示在设置页的多行输入框里：

- 未修改时，输入框里就是内置默认提示词，插件原样使用；
- 修改后**整段替换**内置版本，包括其中的安全约束；
- 美化时，面板里这一轮填写的要求（例如「更正式」「精简一点」）仍会追加在提示词之后；
- 点标题旁的恢复图标可以还原默认值；当前就是默认值时图标置灰；
- 清空后失焦会自动恢复默认值；即使手改了配置文件，空提示词也会在调用前被拒绝。

对话模式的提示词不在自定义范围内，它始终由插件根据当前文档构造。

## 使用

### 打开对话

两种方式，打开的是同一个对话窗口：

- 状态栏左下角的 **AI 按钮**（插件图标组里，目录/大纲右侧）；
- 编辑器右下角的**浮动小人**（可在设置里关掉或换形象）。

窗口里可以像网页版对话助手一样提问，例如「这份文档主要在讲什么？」「把这个结论
改得更简洁」。回答会结合当前打开的文档内容。

### 输入区：对话 / 生成 / 美化

输入框上方依次是三个模式按钮，默认选中「对话」：

1. 选择「对话」「生成」或「美化」；
2. 在输入框里输入内容（美化可以留空）；
3. 点「发送」（或按 Enter）。

「发送」会按当前模式执行：对话回答问题，生成写出新内容，美化整理当前文档。
生成只用于空文档、美化只用于已有内容的文档，不适用时对应按钮会置灰。模式按钮右侧
会提示当前模式的要求；把鼠标停在提示（或按 Tab 聚焦）上，会弹出本轮实际发送给
AI 的**初始提示词**，分成「系统提示词」和「用户消息」两段：对话把当前文档与参考
文件放在系统提示词里，生成/美化则把输入、当前文档和参考文件放在用户消息里。
每段最多预览 2 万字符，过长时保留开头与结尾并标出省略长度。

### 对话

- 在输入框提问，Enter 发送，Shift+Enter 换行。
- 每次提问都会把当前文档作为上下文一起发给模型；空文档也会说明「当前文档为空」。
- 对话只回答问题，不会修改文档。
- 「新对话」开始一轮新的对话；之前的对话不会消失，可以从「会话」里找回。

### 会话与文档关联

对话按**文档**归档：在文件 A 里点开小人，产生的会话都属于文件 A；换到文件 B 再打开，
看到的是 B 自己的会话，不会把两份文档的聊天混在一起。标题栏不再标注当前文件，文档
身份只出现在输入区上方的环境条里。

- 标题栏的「会话」按钮列出当前文档保存过的会话，带标题、消息条数与最近更新时间；
  点一条即可恢复，接着往下聊。
- 「新对话」只是清空当前这轮输入与消息，**文档关联保持不变**，新会话仍在同一个文件下；
  已结束的会话自动收进历史。
- 在会话列表里点 × 可以删除某一条历史；每个文档最多保留 20 条，更旧的会先让位。
- 会话保存在本机（localStorage），关闭面板、重启应用后都还在。未保存到磁盘的新文档
  按标签名归档，保存到磁盘后会以文件路径为准。

### 当前环境：文档与参考文件

对话窗口顶部展示这次请求会带上的环境：当前文档（非空时只显示文件名，不展示篇幅）
和参考文件。两者用不同颜色的描边区分（文档用强调色、附件用琥珀色），不再显示
「参考文件 N」计数标签。空文档会写成「当前文档为空」，不占用发送内容。

点这一行的「＋ 文件」可以选择本地的文本文件（Markdown、TXT、JSON、CSV、代码等）或
**PDF** 作为当前文档的参考资料；已添加的文件会以文件名标签显示在同一行里，点 × 移除。
文件选择框不按扩展名过滤，目录里的文件都会显示，选中后按内容判断。

- **PDF**：在本地提取正文文字后作为参考文件。论文的摘要、正文、标题通常能完整
  取出；双栏排版、公式与表格会被拉平成普通文字。解析在主线程进行，几十页的论文
  通常需要一两秒，面板会显示「正在解析」。加密 PDF、损坏文件会明确提示并跳过。
  极少数没有 ToUnicode 且依赖预定义 CMap 的老式 PDF 可能只能提取出乱码，建议换用
  文本版。PDF 文件最大 32 MB。
- **扫描页**：没有文字层的页面（扫描件）默认会按页渲染成 JPEG，随请求发给模型，
  用来读图片里的文字、公式、表格与图表；混合型 PDF 里文字页仍走文字、扫描页走
  图片。这需要模型支持图像输入，否则服务会返回 400/422，插件会提示你在设置里关掉
  「把扫描页作为图片发送」或换用支持视觉的模型；关掉后扫描页会被跳过。为保证请求
  大小可控，每份 PDF 最多 10 页、每个请求最多 16 张图片，长边约 1400 像素，每张
  压缩到约 20 万 base64 字符以内；超出上限的扫描页会被跳过并在面板里注明。
  扫描页图片**只保存在内存里**，应用重启或页面重新载入后失效，标签会显示「图片需重加」；
  只有图片、没有文字的扫描件在重新打开后会被移除。
- 其它文本文件单个最大 4 MB；含 NUL 字节的二进制文件（图片、压缩包等）会提示跳过。
- 参考文件同样**按文档关联**：在文件 A 添加的文件只在 A 的对话里出现；新开会话不会
  丢失，换文档也不会串用。
- 文件只读取内容，不读取路径、不上传；最多 6 个，单文件约 2.4 万字符、合计约 4 万
  字符，超出部分会截断。PDF 先提取文字（最多 300 页 / 4.8 万字符），再按同样的
  单文件上限截断。
- 对话、生成、美化都会带上这些文件（对话在 system 提示里、生成/美化在用户提示里），
  并明确要求模型把它们当素材而不是指令。美化时参考文件只用于核对事实与措辞，不会被
  整体并入文档。
- 文件的文字内容保存在本机，用于下次打开时继续使用；扫描页图片只在本次打开期间
  保留，不会被写入 localStorage。

### 上下文缓存

对话会把当前文档与参考文件放在 system 提示的最前面，并在多轮之间保持不变，因此可以
利用服务端的上下文缓存，减少重复计费与首字延迟：

- **Anthropic**：对话请求给这段稳定上下文加了 `cache_control: { type: "ephemeral" }`
  缓存断点，后续轮次直接按缓存读取计费；缓存有效期由服务端决定（默认约 5 分钟）。
- **DeepSeek / OpenAI 兼容服务**：缓存是服务端自动完成的，插件只保证结构稳定 ——
  system 永远排在最前，文档与参考文件不会在轮次之间重排；无需也不能附加额外字段。
- 服务端返回缓存用量时，插件日志会记录「缓存命中 / 缓存写入」的 token 数；服务不支持
  或本次未命中时不会显示，而不是显示成 0。
- 美化与生成每次都发送新的正文，不标记缓存断点，避免只写一次却用不上的缓存写入费。

### 生成（只用于空文档）

1. 在输入框上方选择「生成」；
2. 在输入框里写想生成的内容，例如「一份产品周报大纲」；
3. 点「发送」，对话里会出现一条「帮我生成：…」的展示消息和生成结果；
4. 结果消息有「预览 / 源码」两个页签：预览是渲染后的 Markdown，源码是原始文本；
5. 检查后点「写入文档」，或点「重新生成」。

### 美化（用于已有内容的文档）

1. 在输入框上方选择「美化」；
2. 可选：在输入框里写下这次的美化要求，例如「更正式」「精简一点」「按小节分点」；
   不写（直接点「发送」）就交给 AI 自行整理；
3. 对话里会出现「帮我美化一下这份文档」或「帮我美化一下这份文档：…」；
4. 结果消息的**预览本身就是差异视图**：未变化内容正常渲染，新增/修改的内容绿底，
   删除的内容红底并划掉；不再单独放一块逐行差异；
5. 「源码」页签保留最终的 Markdown；点「确认替换」写回，或点「重新生成」。

生成/美化结果在确认前都不会改文档；如果确认时文档已经在期间被修改，会拒绝写入并
提示重新生成。文档开头的 YAML front matter 会被**原样保留**，不会发给模型。

行首「+」→「AI 生成内容」在空文档里会打开对话并直接触发生成；**非空文档**用「+」
生成时仍保持原来的行为：内容直接插入到「+」所在行的下方。

### 浮动小人

- 设置里可以关掉浮动小人，或从猫咪 / 企鹅（动画）/ 机器人 / 幽灵 / 星星中切换形象。
- 企鹅是独立的透明背景动画角色，不套圆形气泡；其它 emoji 形象保留小圆钮外观。
- **按住小人可以拖到编辑器里的任意位置**，位置会在下次打开应用时保留。
- 小人只是另一个打开对话的入口；关掉后状态栏按钮仍然可用。

## 安全与边界

- **文档内容会发送到你配置的服务地址**。不要在不信任的服务上处理敏感文档。
- 密钥由宿主加密保存；插件的日志不会记录密钥，也不会记录文档正文。
- 对话提问会把当前文档作为上下文发送给配置的服务；美化/生成也一样。添加的本地参考
  文件文本（PDF 为提取出的文字）会随下一次对话/生成/美化一起发送；扫描页还会以图片
  形式发送。这些内容都**不会**带上文件路径，也只会发到你配置的那个服务地址。
  不要在不信任的服务上处理敏感文档与文件。
- 会话历史与参考文件内容保存在本机的 localStorage 里，不会上传到 iMark 的服务器；
  清除应用数据或卸载插件会一并删除。
- AI 结果只进入对话消息；**点确认之前不会修改文档**。关闭窗口或请求失败都不会留下
  半个结果。
- 美化时如果 AI 输出被截断（达到模型输出上限）、明显短于原文，或内容为空，
  插件会拒绝这次结果，文档一个字符都不会变。
- 整篇美化/生成的正文上限约 12 万字符；AI 返回内容上限约 18 万字符。
- 不支持流式输出；预览期间文档如果被修改，确认时会拒绝写回并提示重新生成。
- 主进程使用的是 Node 的 `fetch`，**不读取系统代理**。需要代理时，请让服务地址
  可以直连，或在本机起一个反向代理。

## 常见错误

| 提示 | 通常原因 |
| --- | --- |
| 认证失败（401/403） | 密钥错误、过期，或该服务要求 `Bearer` 之外的认证头。 |
| 接口地址不对（404） | 地址没有填完整（例如少了 `/v1/chat/completions`），或模型名不被该服务支持。 |
| 请求过于频繁或额度不足（429） | 触发了限流，或账户余额不足。 |
| 连接被拒绝 / 域名解析失败 | 本地服务没有启动、端口不对，或网络不可达。 |
| 文档在 AI 处理期间被修改 | 请求期间你编辑了文档；重新执行一次即可。 |
