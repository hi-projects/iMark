# 高级表格（Advanced Table）

在光标所在行的最左侧放一个「+」按钮，点开就能插入表格。

按钮、菜单与对话框由**宿主**绘制，所有声明了 `lineMenu` 的扩展会合进同一个「+」菜单；
扩展只负责把对话框里的数字变成一段 Markdown 文本。表格插入后的编辑由宿主实现：
**停留在渲染出来的表格里直接输入，不会被翻回 Markdown 源码**。

## 怎么用

1. 把光标放到想插入表格的那一行（放在行首、行中、行尾都一样）；
2. 点该行左边的「+」（按钮跟着光标走，不跟着鼠标走）；
3. 菜单里选「表格」；
4. 填行数与列数，确定 —— 表格插入在这一行的**下方**，并直接停在渲染出的表格里。

## 在表格里编辑

- **点击任意单元格**就地输入。该格会显示这一格的 Markdown 源码（比如 `**加粗**`），
  提交后重新渲染成最终样式；
- **回车**：提交当前格并移到下一行同一列（已经在最后一行时自动加一行）；
- **Tab / Shift+Tab**：提交并移到右 / 左一格；在最后一格按 Tab 会**自动加一行**；
- **Esc**：放弃这一格本次输入，恢复成修改前的样子；
- **点到别处 / 切换文件 / 保存**：当前格的内容自动提交；表格外的正文照常编辑。

单元格里的 `|` 会自动转义成 `\|`，不会被当成列分隔符；换行会被折成空格
（Markdown 表格无法表示单元格内的换行）。

## 增删行列与整张表

表格四周有一圈小控件：**整表级的三枚按钮在鼠标移到表格附近时出现**，移开就收起；
行/列的增删控件只在能用得上的范围里出现。
它们浮在表格周围，不占版式空间；表格本身仍与正文左对齐。表格自己的上下留白由
`--md-table-gap`（或分别用 `--md-table-gap-top` / `--md-table-gap-bottom`）控制。

表格的隐藏源码行（承载整张表的表头行、后续的表格行）不会成为可输入的行：光标一旦
落进去会被自动挪到表格外的真实正文行；即使输入法组合进行中，文字也不会被写进隐藏源码。
**表格上下紧邻的结构空行保留在源码里**（GFM / markdown-it / Obsidian 会把紧贴表格的
非空行读成表格行，这两条空行是 Markdown 的要求），但渲染态下折成零高度、不接受光标：
表格与上方/下方正文的距离只由 `--md-table-gap-top` / `--md-table-gap-bottom`
（或统一的 `--md-table-gap`）决定，想留多少就写多少。
方向键也翻得过表格：在表格上方按 ↓ 会越过整张表落到它下面第一条正文行，从下方按 ↑ 同理。

- 鼠标放在某一格上时，只出现这一行左侧的 `×` 和这一列上方的 `×`；
- 鼠标靠近某条行 / 列边界线（约 10px 内）时，才出现这条线对应的插入 `+`；
- 鼠标移到表格上，右上角才出现一列按钮：
  `▦`（选中整表）、`≡`（整表对齐）、垃圾桶（删除整表）；
- 点对齐按钮 `≡` 可选 **左对齐 / 居中 / 右对齐**，一次改掉表头与全部正文。
  它改写的是分隔行里每一列的对齐标记（`:---` / `:---:` / `---:`），
  导出到别的 Markdown 编辑器也保持同样的对齐；
- **按住左键拖动**选出一块矩形单元格区域（横向、纵向、斜着拖都按起点格与当前格围出的范围高亮），
  按 **Backspace / Delete** 清空这些格的内容（表格结构不变；删整行 / 整列请点行左 / 列顶的 `×`）；
- 用鼠标从表格上方拖到下方（文档选区覆盖整张表）或按 Ctrl+A 时，表格**仍然是渲染态**，
  整表高亮表示被选中，不会退回 Markdown 源码；
- 选中整张表后按这两个键也会删表。

## 表格边上的删除键

光标停在表格**上一行行尾**按 Delete，或**下一行行首**按 Backspace 时：

1. **第一次**按键不会改文档，而是把整张表选中（整表高亮）；
2. **再按一次**才删除整张表。

这里说的「上一行 / 下一行」是**紧贴表格的那一条可见行**。如果表格和光标之间还隔着空行
（哪怕只有一条），Delete / Backspace 就只是普通的合并 / 删除空行，不会去碰表格 ——
表格只有在光标走到它边上第一行时才会响应这两个键。

这样不会误删表格与正文之间的换行 —— 那个换行一没，Markdown 表格就会当场散架。

光标停在表格上一行行尾按回车时，会在上方插入一个可编辑空行（表格需要的结构空行
自动保留），光标留在新行上，不会跳进表格的单元格。

删除表头行时，下一条数据行会接替成为新的表头（Markdown 表格必须有表头）；
只剩一列时删除该列等于删除整张表。列的对齐方式会跟着列一起保留。

表头滚出视口时，整张表会临时退回等宽源码显示 —— 这是渲染方式的限制
（表格整体挂在表头那一行上），把表头滚回来就会恢复成表格。

不想插入就按 Esc，或者点菜单外的空白处：什么都不会发生，文档一个字符都不会动。

## 插在哪一行

**紧贴光标行的下一行**（第 n 行点的「+」，内容就落在第 n+1 行），中间不加空行。
只有一种情况会自己补一个空行，因为不补就会把文档写坏：

- **光标停在已有的表格里**：插入点会落到**整张表**的下方。Markdown 的表格没法在中间断开，
  从中间插进去只会把原来那张表拆散；落到表下面，新内容是一张独立的表，老表一个字符都不少。

## 行数怎么算

**行数含表头。** 填 3 行 3 列得到的是：

```markdown
|       |       |       |
| :---: | :---: | :---: |
|       |       |       |
```

第一行是表头，第二行是 Markdown 表格必需的分隔行，往下才是内容行。所以
「3 行」= 1 行表头 + 2 行内容，填 1 行就只有表头。

分隔行写的是 `:---:`，也就是把表头与正文一起居中；想改成左对齐 / 右对齐，
用表格右上角的 `≡` 整表对齐（它改写的也是这一行），或手动把这一行写成 `---` / `---:`。

## 权限与实现

这个扩展遵循 VS Code 的扩展信任模型：**扩展代码以你的用户权限运行，没有权限沙箱**。
它本身不访问网络、不读写文件、不碰密钥；启用前仍应确认扩展来自可信来源 ——
这条警告对所有含代码的扩展都成立，不只是 quick-edit。

实现上它只做两件事：在 `package.json` 里声明命令
`imark.quick-edit.insertTable` 与一条行首菜单贡献；被调用时把行数 / 列数变成一段
Markdown 文本，通过 `window.activeTextEditor.edit()` 交给 iMark 插入。
按钮、菜单、对话框和插入位置全部由 iMark 渲染，扩展代码不参与。

它随应用预装、默认启用（可在「设置 → 扩展」里停用）。停用后「+」菜单里的「表格」立即消失。
