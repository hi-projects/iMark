## 0. 一句话背景

用户的原话:"**我想尽量:让插件系统变得对第三方友好,在保证一定安全的情况下,尽可能放权**"。

已拍板的四个方向(别再重新讨论):

1. **功能型插件走槽位** —— 状态栏、命令(含快捷键)、通知、右键菜单、事件钩子;界面仍由宿主画。
2. **UI 型插件开自己的窗口** —— 完整功能 + 自己的界面。
3. **权限变成真门禁** —— 插件代码进沙箱,能力全经宿主申请、宿主可拒绝。
4. **不做"无代码插件"** —— 宿主能力以 API 形式给作者(`imark.ui.notify()` 这类),靠 API 组合。
   作者体验这一轮只做一项:本地开发模式 + 热重载。
5. 现有 `kind:'script'`(主进程 + 完整 Node)保留不动,git-sync / quick-edit 零回归。

**诚实边界(阶段四要写进 README):** 沙箱只对新的 `kind:'sandboxed'` 成立。老式插件依然是
完整 Node。"权限是真门禁"的准确说法是:**装了沙箱插件才是真门禁,装了老式插件仍是告知。**

**交流要求(重要):** 用户看不懂术语,所有解释/汇报都要用**通俗的中文**说清楚,不要甩术语。
每做完一个阶段**停下来汇报一次**,不要一口气推到底。

### 阶段一做了什么(地基,无用户可见新能力)

1. **清单键序抽成单一数据源** `src/shared/pluginFormat.json`(客户端 `validateManifest` /
   `scripts/build-plugins.mjs` / `server/src/validate.mjs` / `src/main/market/pack.ts` 四处读它)。
   目的不是修 bug 而是**防漂移**(原先两份打包实现今天恰好算出同一个 integrity,但没东西拦着它们哪天分家)。
2. **扩展名白名单加 `html/htm`**(外加 `jpeg/webp/woff2/woff`)。白名单本来有**四份拷贝**,必须同批改。
   ⚠️ `build-plugins.mjs` 的 `collectStatic` 收集到 `.html` 会直接 `throw` ——
   只要往 `plugins-src/` 放带 UI 的插件,`npm run plugins:build`(挂在 `predev`/`prebuild`)会让
   **dev 与 build 全线失败**。已在阶段一改掉。
3. **`__imark` 保留段**:包内首段为 `__imark` 的路径一律非法,否则能影子掉宿主的保留资源。
4. **收紧 `imark://`**:原来能读**任意绝对路径**,而主窗口 CSP 允许 `imark:` —— 插件往文档里塞
   一行 `<img src="imark://img/%2F…">` 就是一条读本地文件的通道。现在限制在
   「仓库根 + 当前文档目录 + 插件目录」。
5. **开发模式 + 热重载**:`--plugin-dev=<目录>` 直接以目录为源(跳过打包安装),`fs.watch` 热重载。
6. 顺手收掉两个既有缺口:`Capability.permissions` 全仓无消费点;`imk.vault` 无条件注入不受门控。

### 阶段二做了什么(功能型插件的能力)

- **通知**:全仓原本**没有任何 toast**(11 处裸 `alert()`),现在有右下角气泡 + `imk.ui.notify()`。
  每条带插件名,限流 10 条/分钟,超限写进插件日志。
- **命令 + 快捷键**:清单 `commands: [...]` 或 `imk.commands.register()`。命令面板由原来的
  文件搜索框扩成(原来的 QuickSwitcher)。**快捷键必须注册成(隐藏的)原生菜单项** ——
  Electron 的加速键在 keydown 到达渲染层之前就被拦掉了。撞车时后声明者被摘掉快捷键并写日志。
- **状态栏**:清单 `statusBar: [...]` 或 `imk.ui.statusItem()`。原来 StatusBar 里硬编码的
  git-sync 按钮已删除,改成"谁声明显示谁的"。
- **文件列表右键菜单**:清单 `menus: [{where:'files', ...}]`。
- **事件钩子**:`imk.on('document:save' | 'document:change' | 'file:open' | 'vault:change' |
  'theme:change' | 'config:change', fn)`。`document:change` 有节流(带尾沿)。
- 清单声明与 API 注册**共用同一份宿主实现**(`src/main/plugins/contrib.ts` 的按槽位分表)。

### 阶段二顺手改掉的旧事

- 11 处 `alert()` → 右下角气泡(模态框会打断用户正在做的事)。
- **内置插件跟着应用升级**(`src/main/market/bundled.ts` 的 `upgradeBundled`):
  原来的补装逻辑是"有同 id 就完全不碰",于是用户升了应用也拿不到插件的新能力 ——
  这次的后果尤其明显:StatusBar 里写死的按钮删了,而 0.3.0 的 git-sync 才在清单里声明状态栏条目,
  不升级就是**界面上直接少一个按钮**。规则:**只升不降、只碰 `source:'bundled'` 的、
  授权集合只收缩不扩张、启用态由 `host.install()` 自己恢复**。
- `host.enable()` 加了**幂等守卫**(`Entry.enabledRun`)。原来同一轮启用里 onEnable 会跑两遍
  (补装时 `save()` 启用一次、启动循环再启用一次),一个在 onEnable 里 `setInterval` 的插件会拿到
  两个定时器。注意熔断那条分支是**直接改状态**不经 `disable()`,所以那里也要清 `enabledRun`。

### 阶段二 harness 抓到的 5 个真 bug(读代码一个都没看出来,别再"重新发现")

1. `menu.ts` 的 `built` 从没被置 `true` → 插件菜单冻结在开机那一刻,后来启停插件、注册命令一概看不见。
2. `syncMenu` 只按贡献点快照去重,不含当前上下文 → `when:'editor'` 的命令永远灰着。已把 `commandContext()` 折进签名。
3. `buildAppMenu()` 返回的"被摘掉的快捷键"没人接 → 启动时就撞车的插件永远等不到那句日志。已加 `setKeybindingDropReporter`。
4. `document:save` 只在关窗口时触发(`notifySaveDone` 只被 `saveBeforeClose` 调) → 平时 Ctrl+S 插件收不到。已新增 IPC `doc:saved`。
5. `disable()` 没清 `entry.listeners` / 贡献点 → 停用再启用后每个事件被投递两遍。已在 `disable()` 里 `listeners.clear()` + `contrib.resetApi()`。

## 2. 必须守住的坑(改代码前先看这段)

1. **沙箱性绝不能做成可选字段。** `validateManifest` 是"白名单重建、未知键静默丢弃",
   `runtime?: 'sandboxed'` 这种旁路字段会被旧客户端忽略 → 沙箱插件被当普通 `kind:'script'`
   在主进程以**完整 Node** 跑,安全模型无声蒸发。必须用**新 `kind` 值**(旧客户端硬报错)。
   推广成规则:**将来任何"更安全的形态"都换 kind 值,不加旁路字段。**
2. **四份扩展名白名单要同批部署**(客户端 / 服务端 / 打包器 / `shared`),
   否则出现"服务端拒收 / 打包器跳过 / 客户端能装"的错位。
3. **`imark://` 与 `imk-plugin://` 的路径校验是三层**:逐段 `decodeURIComponent` 后拒 `''`/`'.'`/`'..'`
   → `isSafeRelPath` + `safeJoin` → `fs.realpath` 挡符号链接逃逸。少一层就漏。
4. **绝不接受页面传来的 pluginId**(沙箱 RPC 的身份必须由主进程用 `event.sender.id` 反查)。

## 3. 阶段三(待做):插件窗口 + 沙箱 + 权限门禁

**清单形态**:`kind: 'sandboxed'`(**新 kind 值**,不是可选字段)+ `ui: { entry, width?, height?, minWidth?, minHeight? }`
+ `permissions`。无 `ui` = 纯后台插件,有 `ui` = 带窗口。

### 3.1 协议 `imk-plugin://<pluginId>/<包内路径>`

新增 `src/main/plugins/windows.ts`(处理器可拆到 `src/main/protocol/`)。

- `registerSchemesAsPrivileged` 追一项
  `{ scheme:'imk-plugin', privileges:{ standard:true, secure:true, supportFetchAPI:true, stream:true } }`;
  **绝不给 `bypassCSP`** —— 整个安全模型靠我们下发的 CSP。
- **每插件独立 session** `persist:imk-plugin-<id>`:`protocol.handle` 是按 session 的,
  必须**建窗之前**注册;同时 `setPermissionRequestHandler(() => false)` 关掉所有 Web 权限;
  附赠 localStorage/IndexedDB 隔离。
- 三重防穿越(见 §2.3);防跨插件读:校验 `request.initiatorOrigin` + 锁 `url.host`。
- MIME:`html→text/html`、`js→text/javascript`(不是 `application/javascript`)、`css/json/svg`…,
  全量带 `nosniff` + `Cache-Control: no-store`。
- **CSP 只在文档响应上给**(子资源上的 CSP 会被忽略):
  ```
  default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:;
  font-src 'self' data:; media-src 'self'; connect-src 'self'; worker-src 'self'; object-src 'none';
  frame-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'
  ```
  → 插件页里 `fetch('https://…')` 被直接拦掉,**网络只能走 RPC**。
  `style-src 'unsafe-inline'` 是给 Vue 运行时注入 `<style>` 用的,污染范围仅限插件自己的文档。

### 3.2 窗口

`new BrowserWindow`(不是 `WebContentsView`)+ 独立 session + `sandbox`/`contextIsolation`、无 Node、
`backgroundThrottling:false`、`setWindowOpenHandler` 全拒、`will-navigate` 只许同插件前缀、
`render-process-gone` 记录并带退避重建。窗口几何存 `userData/plugin-ui.json`(不混进 `settings.json`),
恢复时用 `screen.getDisplayMatching()` 夹回工作区。

**生命周期挂钩**:`enable()` 建窗、`disable()` 优雅关窗(2s 超时强杀)、`unregister()` **在 delete 之前**
关窗(升级会 rename 掉插件目录,不先关就是半旧半新 404)、熔断分支强关、卸载后 `clearStorageData()`。

### 3.3 preload 与 RPC

新建 `src/preload/plugin.ts`,走 `electron.vite.config.ts` 第二个入口。

- 沙箱 preload **只能 `require('electron')`**(`externalizeDepsPlugin()` 会把依赖变成运行时 require 直接抛);
  纪律:只 import `electron` 与 `@shared` 类型;构建产物 grep `require(` 只应看到 electron。
- 暴露 `window.imark`:`plugin/log/config/state/on/ui/window/vault/net/git?/secrets?/request`,
  逐层 `Object.freeze`,**没有通用 invoke 透传**;缺权限的能力**不注入**(与 `api.ts` 的
  `imk.git === undefined` 语义一致),运行时闸门仍每次再查。
- **身份防伪造**:统一通道 `plugin:rpc`,主进程用 `event.sender.id` 反查 `webContentsId → pluginId` 注册表,
  再校验 `event.senderFrame === event.sender.mainFrame`。`additionalArguments` 里的 id 只给页面自己看日志,
  主进程永不采信(Linux 上 `process.argv` 能被 `/proc/<pid>/cmdline` 读到,不能放任何密钥)。
- 请求用 `invoke`,但主进程**永远 resolve 结构化结果而不 throw**
  (`{ok:true,value} | {ok:false,error:{code,message,detail?}}`,`E_PERMISSION`/`E_TIMEOUT`/`E_BAD_ARGS`);
  `AbortSignal` → `plugin:rpc-abort` → 主进程 `inflight` 表;参数过 JSON 归一 + 体积上限。
- 宿主→插件:`plugin:event`(`hello/config/theme/vault/doc-saved/tick`),preload **缓存每个 type
  最后一份 payload**,晚订阅也能立刻拿到;反向调用走 `plugin:bridge`,**它就是沙箱版 `PluginRuntime`**,
  于是 `host.ts` 的 `safeCall` 超时/熔断/回滚一行都不用改。

### 3.4 主题

令牌文件从 `src/renderer/src/styles/tokens.css` 移到 `src/shared/theme/tokens.css`
(主进程 `?raw` 内联、渲染层正常 import,一个文件两处消费)。preload 用 `webFrame.insertCSS()` 注入
(**不经过文档 fetch,不受 CSP `style-src` 约束**)+ 设 `documentElement.dataset.theme`;
另开保留路径 `imk-plugin://<id>/__imark/ui.css` 供显式 `<link>` —— 它能过 `style-src 'self'` 的
**唯一原因是同源**,别挪到别的 origin。`__imark/base.css` 做 opt-in 且用 `:where()` 零特异性。

### 3.5 一个窗口同时当执行器

沙箱插件 = 恰好一个 renderer:带界面的加载作者 HTML,纯后台的加载宿主生成的
`__imark/exec.html`(`show:false` + `skipTaskbar`)。作者不必为"有时有窗口"写两套代码。

**定时器节流(会真咬人)**:隐藏页面先 1Hz,约 5 分钟后进入 60s 一次的 intensive throttling。三层应对:
1. **宿主调度器 `imark.schedule.every(ms, name)` 是官方推荐**(主进程 Node 定时器不受节流,
   到点发 `tick`,载荷带 `lateMs`;每插件 ≤32 个、最小 1s);
2. tick 时窗口不存在/已崩 → 带退避重建再投递;
3. `backgroundThrottling:false` 作为作者自己写 `setInterval` 的止血带,文档明说"renderer 定时器是尽力而为"。

三个命令行开关(`disable-background-timer-throttling` 等)**默认不开**,只在实测不生效时才启用
(代价是主窗口也全局不再降频)。另需写进文档:`show:false` 且从未显示的窗口不产生帧 →
`requestAnimationFrame` 不跑;`visibilityState === 'hidden'`。

### 3.6 能力闸门(一次实现,两条传输)

新增 `src/main/plugins/ops.ts`(唯一权威的 op 表,每项声明 `perm | null`、`timeoutMs`、
`maxArgsBytes`、`run(ctx,args)`)与 `src/main/plugins/gate.ts`(`invokeOp` 唯一入口:
op 命中表 → 权限 → 限额 → 超时 → 错误归一)。沙箱走 `ipcMain.handle(IPC.PluginRpc)`;
`api.ts` 改成从 `OPS` 生成,trusted 插件每个方法**再走一次 `invokeOp`**(纵深防御 + 统一审计)。
被拒的调用写进 `entry.logs`(设置页可见"哪一步被拒")。

**`effectiveGrants = granted ∩ declared`**:`InstalledRecord.grantedPermissions` 记录了用户实际同意的集合,
但 `host.ts` 造 API 时用的是当前清单声明 —— 这个语义空洞要在沙箱下补上
(升级新增的权限在重新确认前不生效;`source:'local'` 视为 `granted = declared` 并标注"手动安装,未经确认")。

限额(顺手做):`ui.notify` 10/min、`vault.write` 60/min、`net.fetch` 60/min 且并发 ≤4,超限 `E_BUSY`。

### 3.7 权限词表

7 个旧词(沙箱下语义从"声明"升级为**真强制**)+ 新词 **`ui`**(开自己的窗口 —— 钓鱼窗口是真实风险,
值得如实告知;`ui.entry` 存在却没声明 `ui` 直接报错)+ 新词 **`editor:write`**(往当前文档插入)。

- `settings.set` **v1 不做**(`vaultPath` 是所有仓库边界校验的基准,能改它就等于能重定义边界)。
- `shell` 沙箱下不提供,保留给 trusted。剪贴板读写 v1 不暴露(读剪贴板能拿密码管理器内容)。
- 兼容:**保持"未知权限硬报错"**(静默放行更糟);`ui`/`editor:write` 规定为 **sandbox-only 词**,
  出现在 `kind:'script'` 清单里直接报错。新包带 `engines.imark: ">=0.2.0"`。

### 3.8 路径与资源限制

- `vault:*` 只接受仓库内**相对路径**:长度/`\0`/`\`/绝对路径(含 Windows 盘符)→ 逐段拒 `..` →
  `safeJoin` → 对已存在父目录 `realpath` 校验(挡"仓库内符号链接指向 ~/.ssh")→
  **拒绝任何段首为 `.git`**(`.git/config` 里可能有内嵌 token)。读/写均 ≤1 MiB。
- **写当前打开的文件**是竞态:先 `host.flushDocument()` 再写,然后向主窗口发 `file:external-change`
  让编辑器重载;作者可传 `{force:true}` 承担覆盖风险。**不要默认拒绝** —— 那会让"插件改当前笔记"
  这类最自然的用法不可用。
- `net.fetch` 走**独立内存 session**(避免共享默认 session 的 cookie jar,市场登录态在里面):
  仅 http/https;**手动跟最多 5 跳、每跳重查策略**(自动跟随是经典 SSRF 洞);
  **默认拒内网**(loopback/私有段/链路本地/`.local`/云元数据 169.254.169.254,域名先 `dns.lookup` 全量判定),
  要连本机服务的插件由用户在设置页显式放开;响应 ≤8 MiB、请求 ≤4 MiB;剥离 cookie 头;
  只白名单回传 `content-type/content-length/etag/last-modified`。
- **`git.run` 必须做 args 校验(新洞)**:现在 args 直接递给 `runGit`,trusted 下无所谓(本来就有 Node),
  沙箱下 `-c core.sshCommand=…` / `--upload-pack=…` / `ext::` 等价于任意命令执行。
  拒绝 `-c`/`-C`/`--exec*`/`--upload-pack*`/`--receive-pack*`/`ext::`/`file://`,白名单子命令;
  `credentialArgs/credentialEnv` 留在宿主侧(插件只说"用哪个 secret 槽位",token 不进插件字符串)。

### 3.9 顺手修的既有 bug

`window-all-closed` 是"所有窗口关闭 → quit",有了隐藏的插件执行器窗口之后,
"关了主窗口应用却不退出"会变成安静难查的 bug。改为主窗口 `closed` 时显式 `host.shutdown()` → `app.quit()`。

### 3.10 阶段三的验收清单

- **生命周期**:停用 → 窗口 2s 内消失;卸载 → 窗口消失且 `userData/Partitions/imk-plugin-<id>/` 被清;
  `onEnable` 必抛的测试插件 3 次熔断后窗口强关 + **重启后仍停用**。
- **权限矩阵**:"所有 op 都试一遍"的测试插件,未声明时 `vault.write` 返回 `E_PERMISSION`,
  并用 `stat -c %Y` 证明文件 mtime 未变;把 `installed.json` 里的 grant 删掉后仍被拒
  (证明 `effective = granted ∩ declared`);插件页伪造 pluginId 调 `vault.read` 仍按自己身份判。
- **路径**:`../../.ssh/id_rsa`、仓库内符号链接、`.git/config` 三种都被拒;
  写当前打开文件 → 触发 flush + 编辑器重载且不闪回。
- **网络**:`http://127.0.0.1:…` 默认拒、设置里放开后成功;redirect 到 `169.254.169.254` 第二跳被拒;
  10 MiB 响应在 8 MiB 处失败。
- **节流实测(最易低估)**:纯后台插件同时注册 `imark.schedule.every(1000)` 与自己的 `setInterval(1000)`,
  最小化窗口等 **12 分钟**(跨过两个节流台阶),host tick 应 ≈720 条;若 `setInterval` 明显偏少则启用三个开关重测。
- **兼容**:git-sync / quick-edit 零回归;把沙箱插件包拿**上一版应用**去装 →
  必须看到明确的 `kind` 拒绝,而不是"装上了但不工作"。

### 五条不看代码想不到的经验

1. **`env -u ELECTRON_RUN_AS_NODE` 不是装饰。** 这台机器的 shell 环境里默认就有
   `ELECTRON_RUN_AS_NODE=1`,漏掉它 Electron 会**降级成普通 node** 跑脚本,报出来的错是
   `TypeError: Cannot read properties of undefined (reading 'registerSchemesAsPrivileged')`
   外加一句 `Node.js v24.21.0` —— 看着像 electron 少了 API,其实根本没进 Electron。
   **`npx electron` 一样会被降级。**
2. **harness 必须产出到 `out/main/`**:`createMainWindow` 用 `join(__dirname,'../preload/index.js')`
   定位 preload 和渲染层,放到别处拿不到 `window.api`,界面会静默停在仓库选择界面
   (表现是"所有 DOM 断言超时",很像应用坏了)。而 **`electron-vite build` 会清空 `out/`**,
   所以每次 build 之后都要重新打包 harness。
3. **`--user-data-dir` 是必需的**:harness 会往 `userData` 写桩 `settings.json`、`rm -rf` 那里的
   `vault` 和 `plugins`。每个 harness 的 `main()` 开头都检查了这个开关,没有就 `app.exit(2)`。
   **别加 `--no-sandbox`**(会被权限分类器判成"关闭安全沙箱"而拒绝执行;本项目不需要它)。
4. **合成的键盘输入只认 W3C 旧键名**:方向键要写 `Left`/`Down`,写 `ArrowLeft` 会被**静默丢掉**。
   `Enter`/`End`/`Home` 正常。
5. **测不到的一段(要如实说)**:本机没装 `xdotool`,注入不了 OS 级按键。所以"原生加速键真的按下去
   会触发"这一环模拟不了 —— harness 的做法是**找到那个真实的 `MenuItem` 并调用它的 `click()`**,
   从菜单项往后(发 IPC → 渲染层 → 宿主执行)全都是真的,只有"Electron 收到物理按键并挑中这一项"
   属于框架职责。

### 追加一条实用招数:拿真应用验「老用户升级」

想验"用户机器上装的是旧版内置插件,升了应用之后会怎样",**不用改代码**:

```bash
T=/tmp/imk-upgrade-test
rm -rf "$T"; mkdir -p "$T/vault"
cp -a ~/.config/imarkdown/plugins "$T/plugins"        # 真实配置里的旧版插件目录 + 登记
# 再写一份 settings.json:vaultPath 指向 $T/vault、skipVaultPicker: true、autoSave: false
env -u ELECTRON_RUN_AS_NODE "$REPO/node_modules/.bin/electron" "$REPO/out/main/index.js" \
  --user-data-dir="$T" 2>&1 | grep -E "已升级|已补装"
```

然后核对 `$T/plugins/installed.json` 里的版本与 `sha256sum`。**别拿真实的 `~/.config/imarkdown` 直接跑**,
复制一份再跑。
